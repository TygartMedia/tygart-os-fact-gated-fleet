# Platform feedback from a production-shaped workload — Tygart Media, 2026-10-30
Workload behind every item: 312 pages × 3-stage trio (936 calls), 312 image generations, 312 vision reports, 174 session-video reads (3,093 window reads over extracted frames, three reading pools per recording; the census covers 174 of 175 recordings — the 175th was a sub-10-second recording that extracted 0 frames), a transcription hunt across every audio carrier followed by a full-corpus transcription pass (245 ASR calls, 138,144 words), plus laptop-fleet and CSV tests. All measured, all reproducible from the run folders. Counted program spend: $98.37 of a $153.31 envelope. (Final census and spend per WRAP-UP-2026-10-30.md and NIGHT-LEDGER.md, PROGRAM TOTAL — FINAL; audio totals per video-test/AUDIO-REPORT-FINAL.md.)

## Friction
1. **Chat completions rejects `reasoning` (400 "unknown parameter")** while the Responses API takes it. Same intent, two surfaces, no shared contract — clients discover it by failing.
2. **Reasoning silently eats the completion budget on chat.** With max_tokens 800 and 2,500, calls returned HTTP 200, finish_reason "length", content null — reasoning_tokens 798 / 2,498. usage details do expose reasoning_tokens (good), but a null-content 200 is indistinguishable from breakage until you read them. A finish reason like "reasoning_length" would save every integrator an hour.
3. **No batch API** ("batch API not enabled" on POST /v1/batches). Bulk offline workloads — this night's ~1,560 calls — are exactly batch-shaped; a batch discount + async return would change the economics of agent fleets.
4. **Image-generation usage quantizes** (~11k / ~20k / ~30k / ~41k total tokens) with no documented mapping from prompt to tier. Budgeting per-image cost is guesswork until the manifest exists.
5. **Prompt-cache behavior is inconsistent**: 98.9% hit inside one in-memory chain test; 0–10.5% across production runs with identical prefixes. If it's weather, say so in the docs; engineers will otherwise chase it as a bug.
6. **Long reasoning legs need very high caps** (a CSV judge needed 27.5k reasoning tokens; page judges p90 ≈ 11k). Nothing warns a new integrator that a 24k default will amputate exactly the calls doing the most valuable work. Background Responses mode at standard prices works well and is the right escape hatch — it deserves top billing in the docs.
7. **Direct video input is silently flattened to a still.** Chat `video_url` and Responses `input_video` both return 200 (~11.3k input tokens for a 45 s clip) while the model states in its own prose it received "a single static frame." No error, no flag on the payload. A silent capability reduction is worse than a 400 — the integrator ships a video feature that is actually a photo feature. (Frames extracted client-side work well; ~500 tokens/frame at 854 px.)
8. **sam-3.1 processes everything and returns nothing.** It lives only on /v1/responses (chat 404s and says so — good). A 45 s clip returns 200 in 32 s with `usage.video_frames_processed: 1350` — the console counter moves, the work visibly happens — but the response output, re-read by GET, is a single empty `output_text`. No masks, boxes, or coordinates field exists in the payload. We can see it counting on your side; we cannot retrieve one segmentation from ours. Either expose the result or label the endpoint as metering-only.
9. **Transcription: the working endpoint wasn't discoverable, and every other carrier silently drops audio.** *(Amended 2026-10-30. The original version of this item, written from that morning's hunt, claimed `muse-voice-transcribe-1.0` was unreachable. That verdict was superseded the same afternoon — the correction is below; the silent-drop half of the original item stands.)* What the morning hunt found: `muse-voice-transcribe-1.0` appears in GET /v1/models but returns 404 `model_not_found` on chat and Responses across every content shape (text, input_audio flat/nested, file_id). Meanwhile muse-spark-1.3 accepts audio in every carrier — inline, data-URI, audio_url, files-API file_id (POST /v1/files itself works; purpose `user_data`) — returns 200, and the audio never reaches the model: prompt tokens stay ~1.1k, and a 135 s file measured locally at −17 dB peak was reported by the model as "silence." Fourteen shapes tested; the full matrix is in the run folder. **The correction:** the model does work — through a dedicated endpoint the hunt never found: `POST /v1/asr/transcribe` (multipart WAV, DIARIZATION mode). Settled 2026-10-30 ~18:39 PT — first proven on a single 2 h 22 m recording (16/16 chunks, HTTP 200), then at scale the same day: a full-corpus audio pass over the same 174 recordings ran **245/245 calls OK, zero failures — 2,879 turns, 138,144 words, $3.20 total** (video-test/AUDIO-REPORT-FINAL.md; reconciliation in NIGHT-LEDGER.md). The feedback that survives the correction is discoverability, and it's the expensive kind: the catalog lists the model with no pointer to its one working carrier, while the carriers a client naturally tries either 404 without a hint or accept-and-drop. Hours went into probing fourteen shapes of the wrong doors; a models-list entry that names its endpoint — or a 404 body that does — would have made this a five-minute integration. The pattern across items 7–9 is the same: **accept-and-silent-drop**. A hard error would be a feature here.

10. **A max-effort sync call can burn its entire completion budget on reasoning and return an empty 200.** We sent muse-wonder-1.0 a 27,120-token code-review bundle via chat completions, reasoning_effort max, 20,000 max_completion_tokens: it used 19,998 reasoning tokens, finished with `finish_reason: "length"`, and returned zero content — billed $0.51. Nothing in the sync shape signals mid-flight that reasoning is consuming the budget; the first evidence is the empty message at the end. The identical prompt via Responses background mode at a 60,000 cap completed normally (402s, 13,113 chars), and — credit where due — the failed attempt had warmed the prompt cache, so the retry's input billed 27,110 of 27,120 tokens at the cached rate. Ask: surface reasoning consumption live (or a reasoning sub-cap), so a caller can tell "thinking" from "about to return nothing."

## What worked beautifully
- **Vision honesty.** Spark's image reports flag their own ambiguity ("no label confirming cliff vs. wood vs. soil"), catch composition anomalies a human would miss, and read palette/style at 99.7% across 312 images.
- **Image style discipline.** The generator held a strict house palette across 312 generations and silently corrected palette leaks ("blue sky") in its own prompts.
- **Cross-modal fact discipline.** An empty page (0 chars) was adjudicated NO-OP, rendered as an empty stage, and read back as emptiness by vision — no stage in the pipeline invented content to fill the gap.
- **One calibration note, offered kindly:** Wonder on vision, given an unstructured one-paragraph ask, confidently invented a grand piano in an abstract emblem. Spark with a structured template hedged instead. Structure elicits honesty; the flagship's free-form confidence could use the same governor.
